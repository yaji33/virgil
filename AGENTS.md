# Coding Style

## Comments

- Keep comments short and summarized.
- Add comments only when they provide meaningful context.
- Avoid obvious or redundant comments.
- Prefer no comment over a low-value comment.

## Formatting

- Do not use em dashes.
- Use regular hyphens or rephrase the sentence.

## General

- Prefer clean, readable code over heavy documentation.
- Keep functions and logic self-explanatory when possible.

## Commit Messages

- Generate exactly one line for the selected changes: `type: short summary`.
- Choose one type for the main change: `feat` (new functionality), `fix` (bug correction), `refactor` (restructuring), `docs` (documentation only), `test` (tests only), or `chore` (maintenance).
- Summarize mixed changes together. Do not generate separate messages per file or change type.
- No body, bullets, or explanations. Use `type!` for breaking changes.
- Example: `feat: add persistent demo execution and reconciliation`.
